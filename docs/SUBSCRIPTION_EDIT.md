# 订阅编辑（2026-10-01）

本次修改无需删除重建订阅，数据库仍为 schema 13。当前只完成本地实现与验证，未连接 NAS 或更换生产镜像。

## 使用

在追更列表点击“编辑”，修改剧名、搜索词、季、下一集、待补集、仅补齐/持续追更以及频道范围，点击“保存修改”。保存保留订阅 ID、创建时间和启停状态，不改写已创建任务。

保存带有打开时的版本号。如果后台扫描推进了计划，或其他操作改变了订阅，返回冲突并保留表单输入；点击“重新载入”读取最新计划，再决定修改。重新载入会覆盖当前未保存的表单。新建订阅会清空上一次编辑的内容。

频道范围留空表示跟随启用的默认频道；已有明确频道即使不在默认列表中，也保留在编辑选项中，避免无意丢失私有频道。暂停的订阅编辑后仍暂停，需要显式恢复；已完成且暂停的仅补齐计划允许保存空缺集列表。

## 数据与并发

- 只改变频道范围时保留共同频道的游标和候选；新增频道从零读取，明确范围中移除的频道退出候选选择。
- 改变搜索词、季或集数计划时清空旧候选并重置游标，以发现新计划需要的已发布历史资源。默认范围的游标由下一次扫描建立。
- 编辑通过数据库版本条件更新；扫描结果的候选与游标写入同样检查版本，旧扫描不能覆盖新计划。
- 入队前获得数据库写锁并检查当前版本/启用状态；任务创建、状态事件和订阅推进在一个事务内完成，失败全部回滚。
- 同一订阅、同一季集复用既有任务，多集任务也按覆盖范围复用；资源和归档计划保持原值。若既有任务失败或取消，本轮不推进计划，提示检查下载队列；编辑不隐式创建替代下载或跳过缺集。失败任务可单独重试，取消任务需单独决定重新下载或调整计划。换追另一部剧应新建订阅。
- 扫描摘要只展示与当前订阅版本相符的结果，编辑后等待新一轮扫描；Telegram FloodWait 仍遵守原有禁止重试窗口。

## API

`GET /api/v1/subscriptions/{id}` 返回单个订阅及 `version`。

`PUT /api/v1/subscriptions/{id}` 接受完整计划及 `expected_version`：

```json
{
  "title": "示例剧集",
  "query": "示例剧集",
  "season": 1,
  "next_episode": 12,
  "pending_episodes": [3, 5],
  "continue_tracking": true,
  "channels": [],
  "expected_version": 7
}
```

两个接口均要求现有认证。404 表示订阅不存在；409 的 `subscription_changed` 表示计划已变化，需重新读取；422 表示配置无效或默认范围没有可用频道。PUT 不修改启停状态，仍使用独立暂停/恢复接口。
