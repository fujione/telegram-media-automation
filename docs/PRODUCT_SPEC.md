# 产品规格

## 产品目标

用户配置一个有权访问目标频道的 Telegram 用户账号，即可完成影视资源搜索、候选选择、
持久化下载、归档和电视剧追更。

## 第一阶段范围

### 必须实现

1. Telegram 用户账号登录和持久 session。
2. 配置一个或多个搜索频道。
3. 搜索历史消息并返回结构化媒体候选。
4. 识别电影、电视剧、季、单集和集数范围。
5. 根据身份、集数、质量、语言和文件大小选择候选。
6. SQLite 持久化任务、队列、事件和订阅游标。
7. 下载进度、断点续传、暂停、恢复、取消和重试。
8. 下载到 incomplete，校验后进入 inbox，再归档到 movie/tv 目录。
9. 创建指定影视订阅并轮询匹配的新资源。
10. REST API、Web 管理界面、本地管理员账号、初始化向导和健康检查。
11. 中文/英文界面与配置时区一致的时间展示，包括未登录页面。

Web 概览必须优先呈现“正在处理、需要处理、已结束”等可行动任务统计，并能一键进入相应
服务端筛选结果。搜索候选需将季集、分辨率、编码、语言、大小和匹配度分层显示，任务行
需把状态、进度、错误和归档目标分开呈现，避免把关键决策信息拼成一行文本。

所有会创建或变更任务的 Web 操作必须在请求期间锁定重复点击。一次创建任务弹窗从打开到
成功或显式放弃必须复用同一个幂等键，使网络超时后的安全重试不会创建重复下载。

Web 搜索结果创建任务时必须允许用户明确选择“仅下载”或“下载并自动归档”。自动归档
任务在入队前确认类型、片名、年份和季集信息，并把归档计划固化到任务中；不能在下载
完成后重新猜测用户意图。

任务队列必须支持服务端分页及按“进行中、需要处理、已结束”筛选，不能因默认返回条数
导致旧任务静默消失。每页任务的资源元数据按 ID 获取，不能依赖另一份固定长度资源列表。

创建表单应提供保守、可编辑的结构化身份建议，自动移除搜索词中的季集证据和质量标签；
不能把建议当作已确认身份。裸数字年份不自动提取，以免破坏本身含年份数字的片名。

质量策略必须区分“偏好排序”和“硬过滤”：偏好分辨率、语言与 HDR 只改变候选顺序；
允许分辨率、允许语言和最大文件大小会移除不符合候选。单次 Web/API 搜索可覆盖全局策略，
指定影视追更默认使用全局策略。

频道输入必须接受用户在 Telegram 中能直接看到的完整公开链接（如
`https://t.me/channel_name`），并统一归一化 `@channel_name`、纯用户名和 `-100` 数字
ID。`t.me/c/...` 消息链接可解析为数字频道 ID；无法唯一标识频道的邀请码必须明确拒绝。
保存默认频道前必须使用当前 Telegram Session 解析实体，并按是否存在公开 username 标记
“公开频道”或“私有频道”；不能用“是否显示加入按钮”推断可见性。已保存频道在 Web 列表中
显示 Telegram 标题、类型和启用状态，临时连接失败时明确显示类型尚未验证。
Web 应允许直接发现当前用户账号已经加入的频道与超级群，并用可搜索/可选择的标题和类型
候选填充频道标识，避免私有频道用户必须自行寻找内部数字 ID。

电视剧订阅必须同时表达待补集数与后续追更起点。用户可以填写 `2, 4-6` 仅补缺集后
停止，也可以先补缺集，再从“下一集”继续追更。补较早的缺集不得让后续追更游标倒退；
多集资源一次覆盖的待补集必须一起从计划中移除。

追更扫描必须有独立可配置周期，不能跟随下载队列短轮询反复请求 Telegram。创建或恢复
订阅需要触发及时扫描，同时必须尊重 Telegram 返回的 FloodWait 等待时间。

归档命名固定为 `电影名 (年份)/电影名 (年份).ext` 与
`剧名 (年份)/Season 01/剧名 - S01E01.ext`；未知年份时省略年份。
归档策略可选择移动、硬链接或复制，默认移动。硬链接仅允许同一文件系统；复制和跨卷
移动必须先写临时文件、`fsync`、校验 SHA-256，再提交最终路径。不可静默降级策略，且
任何模式都不能覆盖不同内容的目标文件。

## 用户请求类型

- 电影单次下载。
- 电视剧单集。
- 电视剧集数范围。
- 指定季缺集补齐。
- 指定季补齐并持续追更。

所有路线必须保存原始用户意图，不能把单集请求静默扩大为整季订阅。

## 0.1 验收标准

- 从初始化到搜索、下载、归档和追更形成完整可运行流程。
- 统一状态机拒绝非法转换。
- 任务和事件可在 SQLite 中持久化并重启读取。
- 常见中英文集数格式有数据驱动测试。
- Web 使用本地账号密码和安全会话 Cookie；自动化 API 使用独立 Bearer Token。
- 初始化语言与时区必须真实作用于 WebUI，认证前展示配置不得泄露敏感信息。
- liveness 和 readiness 语义分离。
- 依赖具有 lockfile，测试、lint 和类型检查可重复执行。
