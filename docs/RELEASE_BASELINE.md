# 0.1.0rc1 本地发布基线（2026-09-30）

本候选版本收拢现有工作台、追更可靠性和扫描反馈成果，数据库 schema 保持 13。它是可追溯的开发与运行基线，尚未创建 GitHub Release 或发布预构建镜像。

## 行为与兼容性

- 工作台保留搜索、频道、追更、持续显示的下载队列，以及下载入库和安全替换流程。
- 空订阅频道范围动态跟随启用的默认频道；schema 12 升级后，历史订阅保留原有明确范围。
- 扫描与下载循环分开，逐频道保留游标和退避；候选元数据异常不会中断整轮扫描。
- 扫描显示等待集数、候选数量及拒绝原因。完整成功且计划至少七天未推进时提示用户检查；继续扫描，不自动判断完结或停止订阅。
- 扫描摘要属于内存状态，重启后重新生成。天数依据订阅 `updated_at`；暂停、恢复和计划推进会更新此时间。
- 历史状态迁移不再将一个订阅的消息编号复制给不同频道。修复既有错误游标需显式计划、停止服务、一致备份和事务条件校验，工具默认只预览。
- 当前版本可以保留 schema 13 数据回滚到支持相同 schema 的旧镜像；不兼容的旧程序不能写入当前数据库。恢复旧备份会损失备份之后的记录，不作为默认回滚。

Docker 验收使用缓存的官方 Python 公共镜像镜像源和默认 uv 镜像，未更换现有生产服务。候选镜像仅保留在验收主机，标签 `telegram-media-automation-api:baseline-0.1.0rc1`，镜像 ID 为 `sha256:16d4d40a8cafdedf29630992e33e0a708d46a44a682142f96c937cd3ace20778`；未推送到公开镜像仓库。

浏览器入口 `scripts/check_web_workspace.py` 使用临时数据库、临时管理员和禁用 worker 的服务；不读取个人 `.env`，业务写入由浏览器测试拦截。服务器进程和临时状态结束后清理。截图和日志保存在被 Git 忽略的 `dist/webui-review/`。

复现开发检查：

```sh
uv sync --locked --all-extras
uv run ruff format --check .
uv run ruff check .
uv run mypy src
uv run pytest --cov=telegram_media_automation --cov-fail-under=80
npm ci
npm test
npx playwright install chromium
uv run python scripts/check_web_workspace.py
uv build
```

CI 已增加固定版本 Playwright、浏览器安装与隔离回归入口。上述为本机结果，本候选提交的 GitHub 托管 CI 尚需推送后验证；历史 CI 通过不能替代本候选的托管运行结果。

## 公开内容与后续发布

私人交接、生产部署与诊断记录保留在本机，通过 Git 忽略与 sdist 显式排除保护。公开文件中的个人 NAS 地址和部署目录已改为通用表述。旧 Git 历史中仍有 NAS 地址和目录记录，未重写历史；本次检查不是完整的历史密钥审计。

对外只提供 Docker 部署，用户自行申请 Telegram API ID/Hash，使用自己的账号和频道。正式公开发布前仍需完成预构建镜像、无需宿主机 Python 的首次配置流程，以及按 Docker 快速开始文档完成陌生用户安装验收。版本收尾之后，下一项产品工作为订阅编辑。
