# WebUI 页面设计重构方案

状态：合并式分区工作台已部署到 NAS，并于 2026-09-30 完成扫描反馈更新与验证。当前页面结构以第 12 节为准；前文保留此前方案和迭代记录，不代表当前待实施事项。

## 1. 设计目标

将控制台重构为日常使用的媒体下载工作台。用户进入页面后，可以迅速回答三个问题：

- 我要找的资源在哪里？
- 下载和入库进行到哪一步了？
- 有没有需要我处理的事情？

页面围绕搜索资源、下载入库、追更和替换组织，系统配置作为低频入口。

## 2. 当前页面诊断

以下结论来自用户截图及当前 `web/index.html`、`web/styles.css`、`web/app.js`，不是对未检查的线上页面进行推测。

| 问题 | 当前表现 | 重构决定 |
| --- | --- | --- |
| 信息架构 | 导航使用页面锚点，所有功能同时存在于一条长页面 | 独立页面视图，导航切换当前工作区 |
| 宽屏利用 | 主内容宽度上限 1220px，截图中的宽屏大量留白 | 工作区流式布局，表格和列表使用可用宽度 |
| 首屏优先级 | 大幅宣传横幅、装饰图、账号和运行参数占据首屏 | 首屏展示正在进行和待处理事项 |
| 产品文案 | 正常页面仍展示功能排除说明、实现原理及针对旧误解的解释 | 展示当前功能和操作结果，技术解释进入设置或帮助 |
| Telegram 账号 | 已登录时仍保留整块后台账号区域 | 顶栏状态入口，首次连接和登录失效时才展开操作 |
| 搜索结果规模 | 一次渲染全部候选，放在半宽功能卡片里 | 独立搜索页、完整宽度结果区和分页 |
| 候选判断 | 原始长文件名、大量平级标签、匹配分数占据注意力 | 季集、质量、大小、来源分列，原始信息放详情 |
| 任务操作 | 每行并列事件、暂停、取消、归档、替换等按钮 | 根据状态提供主要操作，其余放详情或更多菜单 |
| 订阅入口 | 创建表单常驻在订阅列表上方 | 默认显示订阅列表，新建和编辑使用独立表单容器 |
| 状态表达 | 控制台登录、Telegram 授权、网络可用性分散展示 | 明确三种状态，异常有具体处理入口 |
| 自动刷新 | 定时刷新整页任务列表，其他系统状态主要靠手动更新 | 局部更新，保留焦点、筛选、滚动和用户正在编辑的内容 |
| 移动端导航 | 小于 470px 时直接隐藏部分导航入口 | 可展开导航，所有功能保持可达 |

## 3. 页面结构

### 3.1 全局框架

左侧导航：工作台、搜索资源、下载任务、追更订阅、频道管理、设置。

顶部：当前页面标题、服务状态入口、管理员菜单。

主体：只显示当前页面内容。支持浏览器前进、后退及直接打开具体页面。

布局规则：

- 桌面侧栏宽度约 216–224px；顶部高度约 60–64px。
- 主体左右间距 24–32px；超宽屏主要增加列表空间，而不是放大字号和控件。
- 搜索、任务等数据页使用可用宽度；登录、设置表单单独限制阅读宽度。
- 详情优先使用右侧抽屉；空间不足时采用覆盖式抽屉或全屏详情。
- 列表页只有一个主要纵向滚动区域，搜索工具和分页保持容易找到；避免页面与多层卡片同时滚动。
- 浏览器页面缩放和窗口尺寸变化均按实际可用空间重排，不通过整体缩放页面来适配。

### 3.2 工作台

首屏内容按操作价值排序：

1. 快速搜索入口。
2. 紧凑统计：进行中、待处理、已入库。点击进入相应任务视图。
3. 当前下载和入库任务，展示具体剧集、进度与主要操作。
4. 需要处理的任务；无异常时不保留大幅空警告卡片。
5. 最近入库及追更概况，列表限制条数，提供“查看全部”。

删除目前常驻的大宣传横幅和装饰轨道图。不在工作台重复展示版本、Worker、时区、复制策略等配置参数。

### 3.3 搜索资源

顶部搜索工具区：影视名称、频道多选、搜索按钮。筛选区提供季集、分辨率、文件大小等条件；不常用项折叠。

频道选择显示标题和备注，可搜索已保存频道；提供“添加频道”入口，不要求每次手输逗号分隔的链接。

结果区使用完整宽度，默认紧凑列表。桌面建议列：

| 资源 | 季集 | 画质 | 大小 | 来源频道 | 操作 |
| --- | --- | --- | --- | --- | --- |
| 可读资源名 | S01E22 | 2160p · HEVC | 2.8 GB | 频道标题 | 下载 |

上表是布局示例，不代表真实资源。

交互规则：

- 每页默认 20 条，支持 50 条；分页与当前结果数量明确可见。
- 原始文件名截断显示，详情中可完整查看和复制，不能无限撑高每一行。
- 来源频道始终可见，原消息入口保留；存在转发来源时在详情中分开展示。
- 集数冲突使用“集数待确认”提示；未知的非关键字段用“—”或不显示，不堆满未知标签。
- 机器匹配分数进入详情，不作为普通用户必须理解的主要字段。
- 同集不同频道和画质的版本可筛选比较；优先通过分列和排序完成，不默认叠加复杂分组。
- 查看详情、创建下载后返回时，保留搜索词、筛选和页码；再次点击同一结果不会意外重复创建任务。
- 初始、搜索中、无结果、部分频道失败、整体失败分别呈现。不能把搜索失败显示为零结果。
- 标签只表达实际已有数据；不能从分辨率或语言猜测是否有字幕、是否包含二维码。
- 不为了视觉效果引入虚构海报、假评分或不可靠的影视匹配结果。

规模约束：当前搜索接口一次返回有界结果列表，没有搜索游标和全量结果总数。第一步可对本次返回结果进行前端分页，但数量须写作“本次找到 N 条”，不能声称已搜索全部历史。更大规模搜索需补充搜索会话、稳定结果排序、服务端分页和继续检索机制；单纯把列表隐藏起来不能解决接口规模问题。

### 3.4 下载任务

状态视图建议：进行中、待处理、已入库、已取消、全部。

列表主要字段：媒体名称/季集、状态、进度、来源、入库目标、主要操作。详细路径、重试次数、技术错误、任务 ID 和事件记录进入详情抽屉。

主要操作随状态变化：

- 下载中：暂停。
- 已暂停：继续。
- 下载失败：重试。
- 仅下载完成且无自动入库计划：入库。
- 集数或身份待确认：确认信息。
- 已入库：查看来源与入库信息；寻找另一版本通过搜索流程完成。

取消等次要或危险操作放入更多菜单，按风险确认。取消任务、删除任务记录、删除媒体文件必须保持不同概念；界面不能暗示取消会删除媒体。

“下载完成”与“已入库”必须分开呈现。具有自动入库计划、正在等待后台入库的任务不误标为需要人工入库。

任务列表沿用现有服务端分页。新增全文搜索、按来源筛选等能力前，先确认接口支持；不可仅筛选当前页却显示成全部任务搜索。

更新时按任务 ID 局部更新进度，不重建用户正在操作的行，不清空筛选或跳回第一页。请求失败显示最近更新时间及重试入口，不把上一次成功的数据伪装为刚更新。

### 3.5 创建下载、入库与替换

使用统一的媒体信息表单组件，明确三种意图：下载并入库、仅下载、替换已有版本。

普通下载默认引导“下载并入库”，提交前核对片名、类型、年份和季集；已有的保守建议及人工确认要求保留。表单内显示目标媒体库位置预览，让用户理解下载完成后的去向。

“仅下载”是清楚可选的独立方式；确认文字说明下载后存放在下载收件箱，之后可从任务页入库。

替换通过“替换已有版本”明确进入，展示新资源与旧文件的片名、季集、来源及目标对照。目标不匹配时阻止提交，存在多个文件时要求选择具体目标。

替换确认保留“原文件将保存备份”的实际影响说明。该说明属于当前操作必要信息，不是历史纠错痕迹。新文件下载和校验成功前不得将旧文件显示为已替换。

所有创建流程保留现有防重复点击与幂等键逻辑；超时重试继续使用同一操作请求，不创建额外任务。

### 3.6 追更订阅

默认展示订阅列表，字段包含：剧名、季、追更起点、待补集数、来源频道、启用状态。

新建按钮打开表单；普通流程填写剧名、季、从哪一集继续、频道。高级区域保留补集范围和补齐后是否继续追更，避免占据普通流程。

订阅详情可展示关联任务；如果接口尚未提供明确关联，不通过剧名猜测任务归属。

扫描时间、最新已入库集数、预计下次检查等字段仅在后端提供对应证据后展示。不得把“下一集”游标误写成“已入库到上一集”，因为游标与真实媒体库状态不是同一事实。

暂停与恢复是主要操作；删除放更多菜单。新增编辑订阅能力需要相应 API，不能仅在表单中表现为已支持。

### 3.7 频道管理

从搜索表单中拆出独立页面，默认显示保存的频道列表。

提供“从已加入频道选择”和“粘贴频道链接”两条添加方式；已加入列表可按标题搜索和选择。展示频道名称、备注、公开/私有、启用状态及验证结果。

输入标签使用“频道链接”，示例为 `https://t.me/channel_name`。其他受支持格式放在输入帮助中；无法识别的链接在输入框附近说明原因。不要常驻一大段解释公开和私有频道的历史问答。

添加前继续使用 Telegram 实体验证。临时网络失败与无访问权限分开呈现，不诱导用户修改正常配置。

### 3.8 设置

分区：Telegram 连接、下载与入库、资源偏好、账号与自动化接口、备份与诊断。

当前支持读取但不支持 Web 修改的参数按只读展示；不能创建保存按钮却不真正保存。Web 修改配置、改密码、编辑订阅等新增能力需作为独立后端工作评估。

版本、Worker、存储容量、时区和详细诊断在此查看。自动化 API Token 不是网页登录方式，不能常驻首页或明文展示。

数据库备份说明保留实际恢复边界；正常使用页面不反复展示 Session、CLI 等实现细节。

## 4. 全局状态及登录

### 4.1 顶栏状态

正常示例：“● 服务正常 · Telegram 已连接”。管理员用户名和退出登录放独立账号菜单。

状态入口可展开数据库、下载工作进程、Telegram、存储的详情和最近检查时间。若检查结果不全，不显示“全部正常”。

状态规则：

- 尚未检查：正在连接；不先显示绿色。
- 服务可用且必要检查通过：服务正常。
- 无法连接服务：服务连接中断；保留可阅读的历史数据并标记未更新。
- Telegram 网络或代理异常：Telegram 连接异常；提供查看连接设置入口。
- 后端明确返回授权失效或未授权：Telegram 需要登录；提供连接流程。
- 浏览器管理员会话过期：回到控制台登录页，不启动 Telegram 验证码流程。

异常摘要只在相关页面显示有意义的影响和处理入口，不在所有页面重复展开完整配置表单。

### 4.2 首次使用

控制台账号登录成功后，只有首次配置或 Telegram 授权失效时进入连接流程：手机号、验证码、必要时两步验证密码。

完成后回到原页面，正常运行期间不再保留后台账号大卡片。换浏览器只影响控制台会话，不改变服务保存的 Telegram 授权。

## 5. 文案与视觉

### 5.1 文案

- 登录页保留产品名、账号密码和简短用途说明。
- 去掉功能排除清单、旧项目对照、针对以往误解的长解释及常驻宣传标语。
- 普通页面统一使用搜索、下载、入库、追更、替换等用户词汇。
- 内部 Session、Worker、Inbox、状态码和分数进入对应详情或诊断。
- 每条错误提示尽可能包含：哪里失败、对当前操作有什么影响、下一步能做什么。
- 不删除替换备份、目标文件核对、删除影响范围等必要安全说明。
- 中英文文案同步维护，不能改完中文后让英文界面回退到旧叙事。

### 5.2 视觉方向

当前视觉采用暖白工作区、石墨色导航和克制的朱橙强调色。通过字号、字重、信息带、分隔线及留白建立层级，图标使用统一线宽的 SVG，不引入海报、封面或外部剧集信息。

建议尺度：

- 正文与主要字段 14–16px；次要信息不承担关键判断。
- 页面标题 22–26px，不使用宣传页级别的巨型标题。
- 普通表单控件约 40px 高；桌面列表行约 64–80px，内容需要时可自然增长。
- 卡片和表格统一边界、圆角和间距；不把每个字段套成独立卡片。
- 颜色只辅助表示正常、等待、警告和失败，必须同时有文字。
- 清晰键盘焦点、完整标签、可复制的完整信息、对比度和减少动效支持。

不把海报墙、复杂动效或主题切换作为第一阶段重点。

## 6. 屏幕适配

| 可用宽度 | 页面行为 |
| --- | --- |
| ≥1200px | 完整侧栏，完整宽度列表；详情空间充足时可并排 |
| 768–1199px | 折叠侧栏；次要列收进详情；抽屉覆盖工作区 |
| <768px | 菜单按钮打开全部导航；列表改成紧凑卡片；表单与详情适应移动视口 |

阈值为设计起点，最终依据内容压力调整，而非仅针对几个设备型号。

移动端保留季集、状态、来源和主要操作。不能通过隐藏导航让用户失去功能入口。弹窗高度受可用视口约束，长表单可以滚动，主要操作不被屏幕底部截断。

## 7. 实现边界和顺序

当前仍是方案阶段，以下仅描述后续开发顺序。

### 第一阶段：结构和关键流程

1. 独立页面视图与真实导航。
2. 流式布局、顶栏状态和按需连接流程。
3. 工作台首屏、完整宽度搜索结果、分页。
4. 任务列表与详情、创建下载及替换表单。
5. 删除正常产品页面的纠错痕迹，统一文案。

### 第二阶段：完整管理体验

1. 频道管理及可搜索选择器。
2. 订阅列表、创建表单和详情。
3. 设置与诊断分区。
4. 状态及时更新、局部刷新及操作反馈。

### 第三阶段：规模与验证

1. 搜索会话及服务端分页等已确认需要的接口补充。
2. 大量结果、任务和频道下的性能验证。
3. 手机、短屏、超宽屏及浏览器缩放测试。
4. 中英文、键盘、焦点、会话过期、断网及安全操作回归。

页面重构按视图、通用组件、数据请求和状态管理拆分当前单文件脚本。是否引入框架由实施阶段结合收益决定，不把迁移框架当作设计成果，也不先重写下载、追更和替换后端。

现有任务分页、资源来源记录、安全替换、自动入库和自动化 API 行为必须保留。后端接口不足的体验明确单独列项，不能由前端伪造。

## 8. 验收标准

- 用户截图对应的超宽屏不再出现窄内容岛；主数据区实际利用剩余宽度。
- 进入工作台首屏能看到正在进行或需要处理的具体任务，不必先滚过宣传、账号和运行参数。
- 导航切换独立内容；刷新、前进和后退保持当前页面语义。
- 正常 Telegram 授权时不存在常驻大登录面板。
- 未登录控制台、服务连接失败、Telegram 网络失败和 Telegram 未授权不互相混淆。
- 500 条模拟候选仅渲染当前页，不把整份结果铺成长网页；可查看全部本次返回结果且数量表述真实。
- 1000 条模拟任务通过服务端分页可访问；筛选不偷偷只作用于当前页。
- 搜索返回、打开详情和提交任务不会丢失当前搜索上下文；超时重试不产生重复任务。
- 下载完成、等待入库、已入库和替换成功分别准确表达。
- 来源频道在搜索和任务中容易看到，原消息和完整文件名可打开或复制。
- 订阅游标不被当作真实入库完成记录。
- 320、390、768、1024、1366、1440、1920、2560px 宽度及 125%、150%、200% 缩放下，导航、弹窗和关键操作均可达。
- 多数页面不出现无意义的横向滚动；长文件名、路径和翻译文本不撑坏布局。
- 对普通用户有用的错误和安全确认保留，正常页面没有旧项目比较与功能排除叙事。
- 生产媒体、任务数据、Telegram 授权和 OpenClaw 自动化接口不因页面重构改变。

## 9. 方案审阅点
